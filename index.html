A terminal you can read.

Open a directory and Claude Code is running. Read the session as a conversation, or drop into the terminal it runs in: one keystroke apart, one session underneath. Beside them, a panel for context, cost and the tab that needs you.

Windows 10 or 11 · needs Claude Code on your PATH, and git for tasks · free, MIT

  1. Tabs that tell you who needs you

    Every tab is a session of its own: its own shell, its own Claude Code, its own directory. A dot says whether Claude is working, has finished, or is waiting for a permission. Beside it, git: commits ahead and behind, and a mark while something is uncommitted.

    Ctrl+Shift+T new tab · windows, tabs and chats come back on launch

  2. Read it as a conversation

    New tabs open on the conversation, built from the transcript of the session: your prompt, the answer, and a card for every tool Claude ran, with the diff of every edit. What you write is typed into Claude Code, so a long prompt arrives whole.

    / commands and skills · @ a file of the project · ↑ earlier prompts

  3. The terminal, underneath

    PowerShell on ConPTY, not an emulation: Claude Code keeps running in it the way it always has. A permission, a question or a plan gets a card in the conversation; an interactive command like /model brings the terminal forward by itself, and it hands the tab back to the conversation when the prompt returns.

    Ctrl+Shift+J changes view · Ctrl+Shift+D puts two sessions side by side

  4. Context and cost, live

    Context against the auto-compact threshold and when the next compaction is due, session and daily cost, your Pro or Max plan limits, the files this tab touched and your recent chats, one click from resuming.

    Ctrl+Shift+B or the title-bar button hides it when you want the full width

  5. Look away. Anthra calls you back.

    A Windows toast and a taskbar badge when Claude asks for something or finishes a turn, only for tabs you are not looking at. The toast says what is asked, the command to run or the file to edit, and a click lands you on that tab.

    Throttled per tab, so a long session never turns into noise

A card per turn, and per tool
Your prompt, the answer in markdown, and what Claude did. Edit and Write carry the diff with its line numbers and counts, and a click on the path opens the diff viewer. Bash carries the command, how long it took, how it ended and the last lines it printed; reads, greps and globs gather into one row, and a tool that fails says why.
It fills while the turn runs
A card appears when its tool starts, with a stopwatch, and closes when the tool does. A line at the bottom counts the turn up and says that Esc interrupts. The view stays at the end unless you scroll up, and then one button brings you back.
A composer that types
Enter sends, Shift+Enter goes to a new line. / lists the commands and skills with their descriptions, @ the files of the project, ↑ and ↓ walk the prompts of this session, and a counter estimates the tokens of what you have written. What it sends is typed into Claude Code rather than pasted, so a long prompt arrives whole instead of as an attachment.
A card when Claude asks
The tab stays where it is and the request appears at the end of the turn. A permission shows what Claude wants to do: the command with its description, the diff an Edit or Write would make, the page to read. Answer with Allow, an always allow that Claude Code itself suggests, Deny, or Deny and stop Claude. A question takes one answer, several, or Other; a plan arrives in markdown, to approve with or without accepting edits, or to send back to planning with an optional note on what to change. 1–9 pick, Enter takes the first choice, Esc declines, and Shift+Tab moves there from a draft in the composer.
The terminal, when it is needed
An interactive command like /model, or a request without a card: the tab moves to the terminal by itself and takes the keyboard with it. When the prompt comes back it returns to the conversation — if it went there on its own; a terminal you chose stays. A line in the conversation says what was asked and whether it was answered on the terminal or is still waiting there. While a card waits, Claude Code’s own dialog stays open in the terminal and the first answer from either side counts; Answer in the terminal takes you there and back. Anthra never answers for you: a closed tab, an error or a request it can’t read leaves the choice to the terminal.

Resuming a chat shows the last 30 turns, with load earlier turns at the top, and a long session opens without keeping you waiting. Compactions, /clear and every change of model or permission mode are separators in the flow. New tabs open on the conversation; Preferences → Conversation changes that, and its Show the terminal when Claude Code asks something decides whether the terminal comes forward on its own. Preferences → Appearance hides the frame around the session, both halves of it: the header above the view and the shortcut bar under it.

Cards need Claude Code 2.1.278 or later. With an older one, or with Answer Claude Code from the conversation turned off in Preferences → Conversation, where it is on by default, every request is answered in the terminal.

Two Claudes, one repository.

Ctrl+Shift+N starts a task: a tab on a new git worktree, with a folder and a branch of its own. One session refactors while another fixes a bug, and neither writes over the other’s files. The tab you started from keeps its branch and its changes.

  1. anthra-site main keeps its branch and its changes
  2. login-migration anthra/login-migration ↑4 Merge
  3. flaky-test anthra/flaky-test ↑1 Pull request
  4. cache-spike anthra/cache-spike ↑2 Discard
Merge
Into whichever folder has the base checked out: a fast-forward when it can, a merge commit otherwise. It refuses while anything is uncommitted, and a conflict undoes itself.
Pull request
Pushes the branch and opens the pull request through the GitHub CLI. Keep the folder leaves the task open for the review.
Discard
Only after a confirmation that counts the commits and changes you are about to throw away.

Git on every tab. The branch of a task, commits ahead of and behind the base, and a mark while something is uncommitted. The panel lists the files Claude touched with their + and − counts; a click opens the diff since the tab started, commits included.

A task lives in <repository>.worktrees\<name> on the branch anthra/<name> by default; Preferences → Tasks sets the prefix. Tasks need git on your PATH; pull requests also need the GitHub CLI, logged in.

Runs on your machine. No telemetry, no analytics, no account.

It writes to your repositories only when you start or close a task, and goes online on its own only to check for updates. An always allow you pick on a card is saved by Claude Code, not Anthra, in its own settings, which can be the repository’s .claude folder.

Straight answers.

Does it change my Claude Code setup?

Not your files. Anthra reads your Claude Code settings files and never writes them. In its own tabs it starts claude with a --settings file that adds a status line and a few hooks, so claude in any other terminal is untouched. When you pick an always allow on a card, Claude Code saves the rule itself, just as it would from its own dialog.

The status line script ships with Anthra. It sends what Claude Code hands it to 127.0.0.1 and nowhere else, then runs your own status line as before. That is where Plan limits come from: on by default, off in Preferences → Panel.

Is the conversation a second Claude?

No. There is one session per tab, and it is Claude Code running in that tab’s terminal. The conversation is drawn from the transcript that session writes, so both views show the same turns, the same tools and the same cost.

What you send from the composer is typed into that terminal as if you had typed it there, which is why Esc, Shift+Tab and Ctrl+C reach Claude Code as the keys they are. A permission, a question or a plan is answered on a card in the conversation, and Anthra’s hooks hand your answer back to that same Claude Code; a request without a card is answered in the terminal.

Why does SmartScreen warn me?

Anthra is not code-signed yet, and SmartScreen warns about unsigned downloads it has not seen often. To check a download, compare its SHA-512 with the sha512 in that release’s latest.yml: 

[Convert]::ToBase64String([Security.Cryptography.SHA512]::Create().ComputeHash([IO.File]::ReadAllBytes("$PWD\Anthra-Setup-<version>-x64.exe")))
Are the costs what I will be billed?

No, they are estimates from a local rate table. On a subscription they are the API-equivalent cost of what you used.

Since 0.9 they match what Claude Code’s /cost reports, a little under it because a few calls never reach the transcript. Earlier versions counted some responses more than once and showed about 2.4 times too much, so expect lower numbers than you remember.

How do I remove Anthra completely?

Uninstall it from Windows Settings (or scoop uninstall anthra), then delete %APPDATA%\Anthra.

Closing a task removes its folder unless you choose to keep it. What can stay in your repositories are the folders of tasks still open or kept, in <repository>.worktrees\<name>, and the task branches, anthra/* by default, since only a discard deletes one. Remove them with git worktree remove and git branch -D.

An always allow picked on a card is a rule in Claude Code’s settings, in the repository’s .claude folder or in ~/.claude, and it stays after Anthra is gone.

I updated from 0.6 and nothing happened.

Versions 0.6 and earlier have no updater, so that one update has to be done by hand. From 0.7 on, Anthra updates itself.
